## Locked Company Definition

> **IntraWeb Technology is a senior-led software engineering company that builds, integrates, modernizes, and stabilizes production systems.**

This statement is LOCKED. It must not be rewritten, paraphrased into a competing root definition, or subordinated to an alternate company category.

Supporting territory:

> We engineer production software and the systems around it.

Potential public-facing messaging (not immutable doctrine):

> Software engineering for systems that have to work in production.

The first statement defines the company. The second explains its territory. The third is messaging and may evolve without changing this foundation.

## Core Interpretation

IntraWeb is an engineering delivery company.

Clients engage IntraWeb when experienced software engineering is needed for a real product, system, application, integration, automation, or operational problem.

The company combines software engineering with systems thinking.

### Capabilities (not a service catalog)

IntraWeb may:

- build production applications
- extend existing products
- implement frontend systems
- implement backend systems
- perform full-stack engineering
- integrate APIs and platforms
- connect systems and data
- modernize existing software
- rescue fragile or difficult systems
- automate workflows
- implement legitimate AI-enabled capabilities
- improve testing and validation
- improve production reliability
- provide ongoing engineering support

These are capabilities. Do not turn them into an undifferentiated service catalog.

### Primary commercial capability territories

1. Product Engineering
2. Systems Integration
3. Modernization & Rescue
4. Automation & AI
5. Production Reliability

These areas intentionally overlap. Do not invent additional top-level capability categories without reporting the need first.

## Recognition Model

Positioning works through recognition, not persuasion.

The visitor should feel located, not impressed.

Located means: "I see my situation in this." Impressed means: "This company is sophisticated." Location is the target. Impression is a drift signal.

### Expanded recognition territory

Valid recognition conditions may include:

- product delivery friction
- fragile existing applications
- systems that are dangerous to change
- brittle integrations
- disconnected applications
- duplicated or conflicting data
- manual reconciliation
- modernization pressure
- implementation debt
- testing gaps
- risky releases
- deployment friction
- production instability
- approved designs that are difficult to get into production
- APIs that do not behave reliably across system boundaries
- workflows dependent on institutional memory
- legitimate AI/automation opportunities requiring production integration

Examples of appropriate recognition language (examples only — not mandatory website copy):

- "The feature isn't difficult. Changing it safely is."
- "Three systems own different versions of the same data."
- "Nobody wants to touch the integration because nobody knows what else depends on it."
- "The design is finished. Production implementation keeps slipping."
- "The application works until the workflow crosses system boundaries."
- "Every release requires somebody who remembers the exceptions."

## Superseded V1 Rules

The following concepts are explicitly superseded and must not be treated as active doctrine:

**A. Exclusive operational-infrastructure identity.**

**B. Absolute statements equivalent to "This is not a technology problem."**
Sometimes the problem IS technical. Do not force a technical or operational diagnosis before examining the system.

**C. Treating "we build" language as inherently invalid.**
IntraWeb builds software. Replacement test: Does "we build" identify meaningful engineering responsibility, or is it generic capability theater?

**D. Fixed 20–150 employee qualification as doctrine.**
Company size may be useful in targeting but is no longer a root qualification. Engineering condition outranks headcount.

**E. Implying defined engineering projects are inherently evidence of agency drift.**
Defined projects are legitimate engagements. Generic package-driven agency positioning remains undesirable.

## Proof and Quantitative Claims

**HC-03 — NO UNSUPPORTED QUANTITATIVE PROOF**

Quantitative claims may appear only when the underlying evidence is known and defensible.

- Metrics must be contextual rather than decorative.
- Never invent, extrapolate, imply, or cosmetically improve an outcome.
- When provenance is uncertain, use qualitative structural evidence instead.
- Do not automatically add metrics anywhere.

Verified metrics are permissible when the underlying evidence exists, the metric is defensible, and sufficient context explains what it measures.

Prohibited:

- invented metrics
- unsupported outcomes
- extrapolated outcomes presented as facts
- implied customer results without evidence
- decorative/floating marketing statistics
- cosmetically improved numbers

## Smart Underneath, Plain on the Surface

Surface language: direct, observational, engineering-plain.
Underlying structure: rigorous, systems-aware, implementation-grounded.
Visible sophistication: low. Actual sophistication: high.

The test: does the language sound like something an experienced engineer or operator would say when describing a real problem? If yes, the register is correct. If it sounds like a framework description or brochure, the register has drifted.

## Anti-Drift Risks (Active)

**Generic agency / capability theater**
Signs: "innovative digital solutions," undifferentiated service menus, package-driven agency positioning, buzzword-led claims without engineering responsibility.

**Consultancy-only positioning**
Signs: framework language, methodology-first presentation, recommendations without implementation consequence.

**AI-as-identity**
Signs: AI adoption sold as the end itself; company framed as an AI consultancy rather than an engineering delivery company that may implement AI-enabled capabilities.

**SaaS product positioning**
Signs: platform language, feature-first presentation, integration catalog as primary differentiator.

**Startup aesthetic / breadth theater**
Signs: energy-first visual design, momentum language, growth narrative, overbroad claims optimized for impression rather than location.

**Exclusive operational-infrastructure reversion**
Signs: forcing every engagement into operational-infrastructure language; treating legitimate product/engineering work as off-position.

## Governing Principle

Every production decision — copy, visual, structural, interactive — is evaluated against one question:

**Does this help the visitor feel located in a real engineering condition this company can take responsibility for?**

If yes: proceed.
If no: revise before build.
If unclear: default to simpler, plainer, more engineering-specific — and stop-and-ask when positioning authority is at stake.
